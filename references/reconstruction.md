# 对象重建与模板适配

仅在实现需要时读取。具体 API、导出和最终验证沿用当前 presentations 技能，避免在这里固化版本路径。

## 坐标与素材

设输入图大小为 `W × H`，目标正文区域为 `(left, top, width, height)`：

```javascript
const scale = Math.min(width / W, height / H);
const dx = left + (width - W * scale) / 2;
const dy = top + (height - H * scale) / 2;
const map = (x, y, w, h) => ({
  left: dx + x * scale, top: dy + y * scale,
  width: w * scale, height: h * scale,
});
```

模板模式可以单独映射参考图中的正文区域，标题另行匹配模板；不要将原图页眉再嵌入模板页眉。坐标、字号、线宽使用一致单位，确认工具使用的像素/点单位，不能默认 1 px 等于 1 pt。

对原生自定义路径，确认 API 是否通过 `position` 缩放 viewport；避免路径点和外框重复缩放。复杂模块按部件重建，不用单一路径承载整幅流程图。

### 图片

- 优先使用原始分辨率文件及工具支持的嵌入字节。最终 PPT 应在移动到其他目录后仍可显示图片，避免依赖外部本机路径。
- 用户要求全图时使用 `contain` 或等效等比留白，不用 `cover` 裁去上下端或边缘。
- 仅有截图时，准确截取必要的图片区域或使用原生图片裁剪。照片外侧的标题、边框和标记尽量独立重建。
- 图像内部的彩线、标注、热图纹理仍是位图。只有存在可验证的坐标/标签源时，才另建对应的原生标记；不能依据肉眼猜边界再称为原始预测。
- 需要压缩时按最终显示大小与清晰度决定，不套用固定的像素上限。裁切和压缩副本放构建目录，保留原图。

## 原生图表与连接线的易错点

仅在当前任务需要原生图表时读取并应用；具体 API 以当前工具文档为准。

- 导出前检查每个系列的数值、散点横坐标和类别长度，数值必须有限。按数据精度保留有效位，不为导出便利擅改真实数据精度。
- 部分导出器会把 `null` 写成 `NaN`。缺失段不能填零或跨段直连；可用带真实横坐标的散点折线，把连续观测段拆成独立系列，补全段单独着色。图例应能区分观测与补全，避免重复条目误导。
- 区间带可用“下界透明面积＋上界减下界的堆积面积＋预测折线”表达；检查上下界、系列顺序及单位。图例隐藏辅助系列，保留实际值与预测值的含义。
- 类别使用真实标签或有意义的时刻值，避免用空字符串控制刻度。长时间序列调整显示间隔，少量类别核对每类均可识别；以最终渲染为准，不固化某次案例的点数或跳步值。
- 隐藏标题后检查是否仍导出空标题节点；仅清理确实为空且无公式引用的标题，保留真实的链接标题。需要包级修复时在副本中进行，保留数值、关系和可编辑性，再走 presentations 的原有验证；不改验证器来迁就输出。
- 原生图表需按 presentations 当前支持的方式保留可编辑数据。由完整、已核对的字面量新建工作簿快照时明确这是新数据载体；原图缺失的数据不能靠快照恢复。
- 箭头端点、`head`/`tail` 命名和连接线图层在不同接口中可能不同。用最终渲染核对方向、交叉与遮挡；网络连线缺失时修复原生线条，圆环文字放在实际色块内部。不要仅凭参数名判断效果。

## Windows PowerPoint 保留模板的可选路径

适用条件：已安装支持该自动化接口的演示软件，当前 presentations 工具的模板导入不能可靠保留母版。先核实实际应用：`PowerPoint.Application` 也可能由 WPS 等兼容软件注册，应按真实应用报告测试范围。不要把此路径当成跨平台前提。

1. 用原生对象接口生成与模板**相同页面尺寸**的正文草稿 PPTX，预先适配正文安全区。
2. 将模板复制到私有构建目录，打开副本与正文草稿。显式选择要编辑的目标页；不要依赖当前活动窗口或当前选中页。
3. 删除/替换用户要求的目标页内容，保留需要的模板装饰及母版。若模板是空白占位页，可直接在该页粘贴正文。
4. 将正文的 shape range 原生复制到模板副本。`Shapes.Range().Copy()` 后用目标 `Shapes.Paste()`，检查粘贴后仍是独立可编辑对象。
5. 必要时复制正文备注，保留来源和内容性质。保存草稿，按 presentations 的最终验证流程另存最终交付文件。
6. 用 PowerPoint 打开**最终文件**，执行 `Slide.Export(path, 'PNG', width, height)` 获取实际渲染并查看。尺寸按该页纵横比设置。

COM 操作须显式持有本次打开的 Presentation 引用。完成后关闭本次文稿；如果连接了用户已有 PowerPoint 实例，不要调用 `Quit()` 或关闭其他文稿。失败时保留源文件和可恢复草稿。

如跨模板移动形状导致样式变化，比较字体、填充和连接线并修复。PowerPoint 可能将字体记录为本地名称，如 `Microsoft YaHei` 与 `微软雅黑`；只有确认是同一字体别名时才在验证策略中认可，不能任意放宽检查。

## 最低验收依据

- 标题/正文在文本框中；框、箭头和模块按部件可编辑。
- 照片/真实算法结果可单独选中与替换，保持完整和比例。
- 存在组不算失败，必须能取消组合并编辑子对象。单个 SVG/EMF 图片不算原生模块。
- 图片占据大部分页面不必然失败，例如整页摄影作品；技术路线/流程图的主体仍须重建原生对象。
- 连接线方向正确。若承诺移动框后连线会跟随，需实际检查端点绑定；只有线条存在不证明绑定成功。
- 模板的母版、logo 和背景仍保留。必要时比较对应素材字节/渲染；无需规定模板覆盖率。
- 对最终文件同时做包结构检查和实际视觉检查，不以形状总数推算“可编辑百分比”或“复刻准确率”。
